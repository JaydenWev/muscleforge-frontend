# API contract and generated client

The backend owns the standard OpenAPI document. This repository pins its own snapshot and `source.json` with the exact backend commit, contract hash and NSwag tool identity/version. Builds and generation do not fetch a live backend or sibling checkout.

```bash
dotnet tool restore
scripts/generate-api-client.sh
scripts/generate-api-client.sh --check
dotnet test tests/MuscleForge.Mobile.UnitTests/MuscleForge.Mobile.UnitTests.csproj -c Release
```

NSwag.ConsoleCore 14.7.1 is pinned in `.config/dotnet-tools.json`; the two NSwag configs target System.Text.Json on .NET 10. The wrapper verifies provenance/hash, runs NSwag and compares generated bytes for `--check`. The fixture is also generated and checked. Schema parsing and C# generation belong to NSwag; there is no custom schema generator. Never hand-edit generated C#. Bash is available through Git Bash on Windows.

Application code uses `MuscleForgeApiClient`. Its small facade reuses generated request/response DTOs, keeps `GetApiStatusAsync(Uri, CancellationToken)` compatible, sets bearer headers per request and preserves normalized base URL prefixes. Login and refresh return generated `AccessTokenResponse`. It owns no token storage, refresh coordination or sign-in UI; MF-14 supplies those.

The facade streams and bounds problem parsing to 64 KiB, exposes typed `ApiError` and `RetryAfter` through `ApiException : HttpRequestException`, propagates cancellation and sanitizes malformed success responses. It does not include raw response bodies in exception messages or inner exceptions. Use normalized HTTPS base URIs ending in `/`. Portable tests cover the facade and the generated parameter/body/enum fixture.

For coordinated changes, prepare and check the backend PR first, then deliberately copy its exact snapshot, update provenance and regenerate in a separate frontend PR. Verify both commits and hashes. Deploy additive server changes before a dependent app update. The route API version, OpenAPI document version and repository build/release revisions are distinct; MF-47 defines released-version compatibility policy.

CI restores the pinned tool, checks regeneration, runs portable tests and publishes the exact snapshot/provenance/config/client artifacts under the frontend revision. The Android job retains the unrelated Python APK payload utility. Native sign-in and device credential-storage acceptance remain MF-14.

Tool reference: [NSwag](https://github.com/RicoSuter/NSwag).
