# Local guest workspace — MF-97

The app opens a device-local workspace without an account, network connection or onboarding. Startup does not read or refresh saved credentials. Existing authentication code and credentials remain in place, but the local core exposes no account route. Optional account backup and synchronization are future MF-96 work; local storage is not a backup. Clearing app data or uninstalling removes it.

Templates can be created, saved, edited and archived locally. The exercise picker offers metadata already present in saved templates, including archived templates, while excluding exercises known to be archived. A new workspace without saved exercise metadata can save empty plans. MF-98 will provide the full offline exercise catalog. Local workout logging and starting from a template are planned for MF-25 and MF-26. The template editor offers kg and lb; its selector starts at kg rather than following a server preference. Unsaved editor changes remain in memory until saved.

## Identity and existing libraries

A stable device workspace UUID and its initial automatic import source are stored together in a versioned non-secret Android preference record. A synchronous disk commit runs off the UI thread and must succeed before the workspace becomes ready; retry reads also confirm durability of a cached record. A malformed stored identity is reported rather than silently replaced. Its `local://device/` scope partitions the same app-private SQLite database used by earlier releases; it is not an account, credential or HTTP endpoint. Existing HTTPS account/server partitions remain intact. SQLite schema version 3 adds import receipts to the populated version 2 database without recreating template tables.

When creating the guest identity, the app binds automatic import only to a previously verified version 1 workspace whose normalized server matches the configured server. A version 2 signed-out marker does not select a source. Later starts and failed-import retries use that original binding, rather than automatically selecting whichever account or server is current. Other retained libraries can be selected explicitly under **Settings → Existing libraries**, including libraries left after sign-out. The selection shows the full server root, a bounded account identifier and the template count; copying never alters or removes the original partition.

Each import runs as one transaction. Template, exercise and set IDs, order, revisions, archive state, rest and exact integer weight values are retained. An ID already present in the guest workspace without a receipt for that source is reported as a conflict and left untouched. Import receipts make retries idempotent: a previously copied template is not overwritten or recreated even if the guest copy has since been edited or deleted. Source changes after import do not overwrite guest changes. Errors and cancellation before commit roll back the import; cancellation cannot undo an already completed commit. Library listing and import have explicit bounds of 1,000 libraries and 10,000 templates per library; exceeding a bound reports an error without a partial import.
